title: 能力边界与数据限制
---

# 只读

只能执行单条 SELECT。写操作、DDL、存储过程一律不做，也没有权限做。

用户要求修改数据时，说明边界并指出该走审批或运维流程。

# 表白名单

只有数据源白名单里的表可查。遇到「表不在白名单」就换表，不要尝试绕过。

# 敏感列

口令哈希、密钥类列被屏蔽，查询会被直接拒绝。需要用户维度信息时用非敏感列。

# 跨库关联

不能跨库关联。需要跨库数据时分别查，再人工对照，并在回复里说明两边口径可能不同。

# 结果规模

单次查询返回有行数上限。统计类问题用聚合，不要拉明细再自己数；确实需要明细时先聚合定位，再取小样本。

# 结果可复核

每次取数都要给出实际执行的 SQL、时间字段与区间，让用户能自己复核。没有 SQL 的数字不可信。

# 不可做的事

- 不做因果归因与业务建议
- 不做报表发布与看板搭建
- 不代替审批人做决策
- 不猜测缺失的数据，不估算未查询的数字

# 失败时怎么说

说明失败在哪一步：表或列不存在、被白名单拒绝、超时、结果为空。给出下一步建议（换时间字段、换表、缩小范围），但不要伪造结果。
