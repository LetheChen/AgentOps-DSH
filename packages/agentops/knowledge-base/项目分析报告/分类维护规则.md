# 项目分析报告分类维护规则

## 顶级知识域

项目分析、GitHub 项目研究、技术选型、部署验证和方案案例统一归档到 `project_analysis`。Agent 不得为单篇文档新建顶级知识域。

## 二级目录

目录最多两级，第一级仅使用以下稳定分支：

- 技术分析：本地部署、架构实现、性能评测
- 产品与市场：商业分析
- 治理与风险：安全合规
- 任务归档：任务报告
- 待复核：自动归档

## 自动维护顺序

1. 归档前先查询已有分类目录，优先复用语义相同或相近的目录。
2. 没有匹配目录时，才创建新的二级目录。
3. 标题、正文和来源都足以支持分类时，直接归档到匹配目录。
4. 分类置信度不足、来源不明或存在冲突时，归档到 `待复核/自动归档`。
5. Agent 自动创建的目录标记为待确认；复核后由人工确认。
6. 目录名使用简短中文，不包含日期、版本号、任务编号、个人姓名或未核实的宣传口径。

## 发布顺序

1. 创建 Raw 草稿，写入 `targetSpaceId` 和 `categoryPath`。
2. 执行重复、敏感信息、同名页面和关联页面检查。
3. 无阻断项后发布为 Wiki 页面。
4. 发布页进入同版本检索、智能问数引用和记忆星云投影。
