# 用法

回答统计类问题前先在这里找口径；找不到就用最直白的人数/单数口径，并在回复里写明分子、分母与时间字段。

字段名以 `describe_database` 的返回为准，本文只定义口径，不复述列名清单。

# 口径三要素

每个指标都必须能说清三件事：分子是什么、分母是什么、按哪个时间字段落区间。缺一项就会和别人的数字对不上。

# 审批单量

按 `audit_records` 中业务发生时间落在区间内的审批单计数。同一申请单重复提交按多条计，需要去重时用申请单号。

不要用主键计数代替申请单计数：一次请求可能产生多条记录。

# 通过率、转人工率、驳回率

分母是**当期已出决策**的单量，不是当期全部单量。仍在处理中的单不计入分母，否则分母被稀释，比率偏低。

三个比率的分母必须一致，加起来才接近 100%；对不上说明混用了不同分母。

# 平均审批时长

只统计已有完成时间的单：时长为完成时间减业务发生时间。未完成的单不参与平均，否则会把平均值拉低。

需要看尾部时用分位数而不是平均值；样本少于 30 条时不要给分位数，直接说明样本太少。

# 退回重提率

指被退回后再次提交的申请占比。分母是当期被退回的单量，分子是其中出现二次提交的单量。

同一申请单号出现多条记录是重提的信号，但补录、撤销重开也会产生多条记录，需要结合状态判断。

# 模型调用成本

按模型调用日志的 token 用量与定价表相乘求和，输入与输出分别计价，币种为人民币。

缺定价行的模型要在回复里点名，不要按 0 成本计入。

# 人均处理量

按处理人维度分组计数。重名用户按用户标识分组，不要按用户名字符串分组。

# 数据完整性提示

指标里出现「约」「左右」时要说明原因：是抽样、是数据覆盖不全，还是去重口径不确定。没有原因的近似等于编造。
