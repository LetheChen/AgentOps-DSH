# 用户说「多少单」怎么算

默认按申请单计数，并在回复里说明是否去重。用户追问明细口径时，给出单号维度的数字。

# 用户说「多少人」怎么算

按申请人去重计数，不按记录条数。同一人多次申请算一个人。

# 用户问比率没给分母

默认用当期已出决策的单量作分母，并在回复里点明。用户如果要「占全部单量」，那是另一个口径，重新算一次。

# 用户给的范围很模糊

「最近」「近期」「这阵子」按滚动七天处理；「这段时间」先问清起止，或者给出最近七天并说明可以改区间。

# 数字和用户手上的报表对不上

按顺序排查：时间字段是否一致、区间开闭是否一致、分母是否一致、是否去重、是否包含未完成单。逐条说明差异，不要改口径去凑对方的数。

# 查出来是空结果

先确认数据覆盖区间与时间字段，再确认筛选值是否写错（状态枚举、用户名大小写、组织标识）。确实没有就回答没有，并说明查的是哪个区间、哪个字段、哪个筛选条件。

# 用户要「原因」

问数只给数据，不给因果结论。可以给出分组对比（按天、按人、按状态），把归因留给用户或分析类 Agent。

# 用户要导出或写操作

只读查询不做导出、不改状态、不触发审批。需要这些操作时说明该走哪个流程。

# 用户问趋势

给出按天或按周的序列，并说明区间与聚合粒度；样本少于两周时提示趋势不成立。
