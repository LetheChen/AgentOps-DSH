# 一级目录

知识库按长期用途划分一级目录，文档体裁不直接决定一级目录：

- 财务制度：财务制度、报销和审批规则；平面结构。
- 人事政策：员工政策和人事流程；平面结构。
- 运维手册：发布、告警、值班和恢复规程；平面结构。
- 办公协作：周报、会议记录、系统规划和任务总结。
- 项目分析报告：项目研究、选型、竞品和方案评估结论；平面结构。
- 技术文档：架构、接口、部署、故障排查和工程规范。
- 学习资料：课程、书籍文章和学习笔记。
- 业务资产：先按业务划分 `智能问数` 与 `智能审批`；问数口径和查询方法归前者，审批数据目录与能力边界归后者。
- 内容创作：视频模板、动效卡片、周报模板和内容规范。
- 待复核：无法确定归属或存在分类冲突的材料；平面结构。

# 归档判定顺序

1. **先看知识归属。** 文档是否属于财务、人事、运维等强治理领域？若是，进入对应平面领域。
2. **再看长期用途。** 办公过程记录进入办公协作；技术实现与维护资料进入技术文档；学习吸收资料进入学习资料；可复用媒体模板进入内容创作；问数与审批知识按业务进入业务资产。
3. **再看结论性质。** 项目研究、技术选型、竞品比较和方案评估的结论进入项目分析报告，不复制到技术文档。
4. **最后看文档类型。** 只有在已确定的一级域内，才选择周报、会议记录、架构设计、接口说明等二级分类。
5. **低置信度不硬分。** 来源不明、主题跨域且无法判断主要用途、或分类冲突时进入待复核。

# 分类标准

- 一个文档只选择一个主要知识域；关联主题通过 Wiki 链接表达，不重复归档。
- 文件格式、扩展名、作者和日期不参与一级域判断。
- 项目名称、年份、版本号不创建目录；这些信息保留在标题、来源或正文中。
- 财务制度、人事政策、运维手册、项目分析报告和待复核保持平面结构，不再建立二级目录。
- 能复用的模板进入内容创作；由模板生成的具体周报进入办公协作的周报分类。

# Agent 执行顺序

1. 读取标题、正文、来源任务和已有分类目录。
2. 按“知识归属 → 长期用途 → 结论性质 → 文档类型”给出一个目标空间，不给出多个并列答案。
3. 目标空间是平面域时，分类为空。
4. 有分类的空间先复用已有目录；必要时最多创建两级。
5. 置信度不足时选择 `review`，在草稿中记录原因。
6. 创建 Wiki 草稿，执行重复、敏感信息、来源和关联页面检查。
7. 无阻断项后发布；变更分类和发布动作都进入操作日志。
