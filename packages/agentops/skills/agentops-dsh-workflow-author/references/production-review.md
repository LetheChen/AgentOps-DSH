# 生产工作流审查清单

逐项给出证据；任何一项为“未知”都不能宣称生产可用。

## 身份与边界

- [ ] 用户明确要求新建或修改该工作流。
- [ ] `workflow_id` 全局唯一且稳定。
- [ ] 目标文件路径是 `agentops/workflows/<workflow_id>.yaml`。
- [ ] 已有同名文件时，用户明确授权覆盖并确认了范围。
- [ ] 没有把一次性任务错误地固化成工作流。

## Agent 与工具

- [ ] 每个 `agent` 引用都在 `agentops/agents/` 中存在。
- [ ] Agent 的职责与节点职责匹配。
- [ ] role_prompt 中调用的每个工具都在 `agentops/mappings/tool-map.yaml` 有映射。
- [ ] 生成后的 preset 确实挂载这些工具。
- [ ] 需要的 ACL、数据源、通知实例、SSH 实例已经存在。
- [ ] 没有使用未迁移工具或臆造工具名。

## 输入与输出

- [ ] 输入只有 `string/integer/number/boolean/array`。
- [ ] 必填性、默认值和业务描述一致。
- [ ] 节点输出端口的键稳定且下游真实消费。
- [ ] 终止节点提供最终交付端口。
- [ ] 每个 role_prompt 明确最终 JSON 契约。
- [ ] 失败结果是结构化失败，不是伪造成功。

## 拓扑

- [ ] `after` 覆盖全部必要依赖。
- [ ] `outputs.to` 全部指向存在的节点。
- [ ] 没有循环依赖。
- [ ] 分支节点各自可终止，未选分支不会产生副作用。
- [ ] 没有 `command/gateway/parallel_branch/while` 节点。
- [ ] 没有 `inline_agent`。
- [ ] 没有 `handoff`。

## 校验

- [ ] `dag_validate` 返回 `ok: true`。
- [ ] 记录了校验返回的层级或关键 error 证据。
- [ ] 落盘后 `dag_catalog` 能看到新工作流且状态有效。
- [ ] 重新读取文件，内容完整。
- [ ] 明确说明“已创建但未执行”。

## 安全与副作用

- [ ] 远程写入、通知、审批、删除、发布等副作用已明确告知用户。
- [ ] 未经另行授权没有运行工作流。
- [ ] 凭证、Webhook、密码没有写进 YAML。
- [ ] 敏感信息只通过能力中心实例引用。
- [ ] 失败路径不会自动重试不可恢复的外部操作。
