# 审批操作路由

> 本 skill **不是**审批规范本身。它只做两件事：给你**通用审批操作的安全边界与执行骨架**，并告诉你**审什么单据就去知识库查什么规范**。

规范细节（字段归属、字典值、联动规则、易错点）都在知识库里，按单据类型分篇。**不要凭本 skill 或记忆直接执行审批**，必须先查对应规范。

---

## 一、什么时候激活

用户要求**审批 / 代审 / 办理 / 提交**任何业务单据时，先加载本 skill，再按下文定位对应规范。

典型触发：

- 「帮我审批这个业务需求申请」「代审这单」「提交这个审批」
- 「帮我把这张单据按规范走完审批」
- 用户给出一张单据让你办理

**不激活**：纯审批状态查询、审批流程规则说明、不涉及实际办理的咨询。

---

## 二、先查规范，再动手（强制）

审批操作**必须**遵循对应单据的详细规范。本 skill 只给通用操作，**不复制任何一份规范的正文**。

### 定位规范的步骤

1. **判断单据类型**：从用户给的信息里识别是哪一类单据（需求申请、报销、采购、请假等）。识别不出类型，先向用户确认，**不要猜**。
2. **查知识库**：用 `knowledge_search` 检索该单据类型的审批规范，按下方「三、规范索引」选对空间和关键词。
3. **读命中内容**：检索返回的 `text` 与 `locator` 就是规范正文。按它执行；多条命中时优先取该空间内标题最贴合的一条。
4. **检索不到就停下**：知识库没有对应规范时，如实告知用户「知识库中没有该单据类型的审批规范」，请用户决定（提供规范或改用其他方式），**严禁凭记忆或经验自行编造审批步骤**。

> 检索用的是 BM25 语义匹配，关键词不必和标题一字不差，但要用**该单据类型的业务叫法**，不要用泛化词（如只搜「审批」）。

## 三、规范索引

按下表定位规范所在空间与检索关键词。空间名对应知识库 `业务资产` 域下的分类目录。**新增单据类型时，在此表加一行，并在知识库对应目录新增一篇规范，不必改动本 skill 的通用部分。**

| 单据类型 | 知识库空间 | 检索关键词（示例） |
|---|---|---|
| 业务需求申请（OA 需求评估） | `smart_query`（业务资产 · 智能审批） | `业务需求申请 代审`、`需求评估 审批` |
| 报销类单据 | `finance`（财务制度） | `报销 审批`、`差旅报销` |
| 采购申请 | `finance`（财务制度） | `采购 审批`、`采购付款` |
| 请假 / 调休 | `hr`（人事政策） | `请假 审批`、`调休` |
| （新类型） | `<空间>` | `<关键词>` |

> 说明：空间标识与分类目录以知识库实际目录为准。若某类单据的规范放在其他空间，按其实际位置调整本表。

## 四、通用审批操作骨架

下面这套**所有单据审批共用**，无论审什么单据都照做。具体字段、字典、节点顺序以查到的规范为准。

### 1. 安全边界（不可越过）

- **授权范围**：只在用户明确授权的单据、部门、金额/业务范围内操作。超出范围先停下询问。
- **用户决策项不代判**：凡是规范标注「需用户决策」的字段（如评审结论、人选、日期、金额等），**不替用户决定**，先向用户确认取值后再填。
- **发起人原样信息不改写**：申请人、申请内容等发起人填写的信息保持原样，不改写、不补写、不杜撰。
- **受控值用受控值**：规范里给了字典值的，一律用字典值，**不自造、不改写自由文本**。字典没有对应值就说明，不硬凑。
- **提交前必须确认**：把**待提交内容**（含处理意见/署名）展示给用户并取得确认后，才执行提交。
- **不绕过控件**：按规范描述的控件交互方式操作（选人、选树、下拉用真实指针事件等），不直接改底层值、不做静默绕过。

### 2. 执行骨架

1. **确认单据与类型**：核对用户给的单据、确认是哪一类型，必要时向用户确认。
2. **查规范**：按第三节定位并读取该类型的详细规范。
3. **打开单据**：按规范描述的方式进入单据（如通过待办跳转地址直接导航，不必模拟列表点击）。
4. **核对字段**：按规范的「字段归属」确认哪些字段代审可填、哪些必须用户确认，逐项落实。
5. **填值与联动**：填入确认过的内容；涉及联动字段（如归口部门、审批人）按规范回读核对。
6. **提交前展示**：把待提交内容展示给用户确认。
7. **提交**：按规范执行提交动作，注意规范里说明的系统提示（如防重复提交锁）不是失败，不要重复点。
8. **提交后验收**：按规范的验收口径**回读验证**，确认表单状态与提交记录都正确，再向用户汇报。

### 3. 验收口径（通用）

提交成功以**实际回读验证**为准，不只看提交动作有没有发出：

- 处理意见区新增了本次署名与时间。
- 表单由编辑态转为只读态。
- 提交/操作按钮按预期消失。

**以上需同时成立才算成功；只满足部分，按未完成处理，如实报告，不要报告成功。**

---

## 五、失败与边界处理

| 情况 | 怎么做 |
|---|---|
| 知识库没有该单据的规范 | 如实告知，请用户提供规范或改方式，不编造 |
| 单据类型识别不出 | 向用户确认，不猜、不默认 |
| 需用户决策的字段 | 向用户确认取值，不代判 |
| 超出授权范围 | 停下询问，不继续 |
| 控件按规范操作不生效 | 按规范的易错点换方式；仍失败则如实报告，不硬绕 |
| 提交后回读不通过 | 如实报告未完成与缺哪一步，不报成功 |

---

## 六、交付

审批完成后，向用户汇报：**审的是哪张单据、依据的是哪份规范、执行了什么、提交结果与验收结论**。失败时说明失败点与用户下一步可怎么做。
