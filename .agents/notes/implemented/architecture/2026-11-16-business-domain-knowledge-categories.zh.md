# Agent Note: 业务领域知识空间与自动归档

Status: implemented

[English](2026-11-16-business-domain-knowledge-categories.md) | 中文

## Problem

知识库仪表盘原先只有一小组扁平空间，名称混用了业务归属和文档体裁，也没有为办公记录、学习资料和技术文档提供稳定的宏观入口，Agent 只能猜测文档应放在哪里。Wiki 工作台同时演变成很高的三栏页面，长草稿预览会截获滚动，并挤占审核操作。

## Decision

内置目录按知识长期用途组织。`finance`、`hr`、`ops`、`project_analysis` 和 `review` 是平面空间。`office_docs`、`learning`、`technical_docs`、`smart_query` 和 `content_creation` 使用稳定的文档类型分类，最多两级。平面空间不创建分类，Wiki 发布也不除外。

草稿创建按“知识归属 → 长期用途 → 结论性质 → 文档类型”自动选择目标域。项目结论进入 `project_analysis`，办公记录进入 `office_docs`，学习资料进入 `learning`，技术实现文档进入 `technical_docs`，数据知识进入 `smart_query`，可复用模板进入 `content_creation`，无法判断的材料进入 `review`。显式指定目标域时可以覆盖分类器。Wiki 工作台展示归档顺序、自动导入控件、双栏审核队列，并把分类、索引和日志放到主审核区下方。长草稿正文默认折叠，通过明确操作展开全文。

## Alternatives considered

**继续按内置工作流划分一个域。** 否决，因为办公报告、学习笔记和技术文档会跨工作流出现，工作流归属过窄，不适合长期检索。

**把文档类型作为顶级目录。** 否决，因为周报、会议记录和系统规划都属于办公协作，而项目分析与架构文档即使都偏技术，也需要不同的知识归属。

**所有知识域都保持平面。** 否决，因为办公协作、学习资料、技术文档、数据问答和内容资产都有稳定重复的文档类型，值得保留一级分类。

**强制所有知识域都使用分类。** 否决，因为财务、人事、运维、项目分析和待复核是政策型或小而稳定的集合，再加目录只会增加导航成本。

**把完整草稿放进内部滚动框。** 否决，因为滚轮会长时间停留在数千像素的预览框内，让页面看起来无法滚动。

## Consequences

十个仪表盘入口现在对应稳定的长期知识用途。文档只选择一个主要领域，相关内容通过链接关联而不重复归档。平面领域保持直接访问，有分类的领域展示稳定文档类型。仓库打开时会清理平面领域的旧分类。确定性路由只是第一层判断，Agent 在上下文更明确时可以显式指定目标域。低置信度材料保留在 `review` 中，而不是被错误归类。

## Testing

知识库测试覆盖自动领域路由、平面空间发布、分类空间发布、仅分类移动、持久化和旧数据迁移。客户端测试覆盖分类树与 Wiki API。浏览器在 900、1280 和 1920 CSS 像素下验证页面滚动、仪表盘打开、Vault 打开、草稿预览折叠和控制台零错误。
